Практическая «Работа с файлами и мультимедиа» (пошаговая) — ответы и ожидаемые значения

Шаг 1. После запуска сервера появляется папка uploads. В консоли — 404 только для js/upload.js.
Шаг 2. not_a_photo.jpg — тип image/jpeg (браузер определяет по расширению); картинка не показывается,
       потому что внутри текст. «Будет отправлено» = исходный размер (3,3 МБ), т.к. shrink — заглушка.
Шаг 3. Внутри not_a_photo.jpg — обычный текст; JPEG в Блокноте начинается с символов «яШя» (байты FF D8 FF)
       и слова JFIF/Exif. Сообщения: см. таблицу 2 методички; седьмое фото — «не больше 6».
Шаг 4. До исправления убранное фото открывается по blob-ссылке; после — ERR_FILE_NOT_FOUND.
       revokeObjectURL также вызывается после публикации (шаг 7) и при замене/отказе видео (шаг 8).
Шаг 5. 3,3 МБ → ~73 КБ (в ~45 раз). Качество 0.5 — ~16 КБ, 1.0 — ~580 КБ (замерено для hotel_room.jpg).
       У phone_photo.jpg в свойствах: GPS широта 53°11'45,2", модель камеры Smartphone A1, 3000×4000.
       В уменьшенной копии метаданных нет: холст хранит только пиксели.
Шаг 6. sticker.gif → {"error":"Такой тип файла не принимается"} (415); not_a_photo.jpg принят,
       потому что сервер поверил заголовку Content-Type.
Шаг 7. Запрос upload для hotel_room.jpg — ~73 КБ. В файле в uploads нет GPS и модели камеры.
       Текст <b>привет</b> показан как есть, с угловыми скобками (escapeHtml).
Шаг 8. Код 206 Partial Content; в запросе Range: bytes=…, в ответе Content-Range: bytes X-Y/205425.
       preload="metadata" — грузить только начало, а не все видео сразу.
Шаг 9. not_a_photo.jpg → {"error":"Содержимое файла не совпадает с его типом"}.
       Проверки сервера: тип из списка (415), размер ≤ 30 МБ до чтения тела (413),
       содержимое = заявленный тип (415), случайное имя (перезапись, ../), экранирование при выводе.
Шаг 10. Исходные ~3,3 + 3,3 + 0,2 МБ ≈ 6,8 МБ; на сервере ~0,07 + 0,07 + 0,2 ≈ 0,35 МБ.
